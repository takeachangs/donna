# Higgs Audio Hackathon 2026 — rules & submission (source: https://www.boson.ai/hackathon, fetched 2026-10-23)

Date: Fri Oct 23 (demos Sat ~3pm per blog). Requirement: Higgs Audio must be a meaningful part, "not simply the final TTS output layer." $100 free credits (claim in Workspace → API key).

## Tracks (pick closest; name primary if spanning)
1. Put a Face to the Voice — Higgs Avatar; tutor/host/character/companion.
2. Conversation as the Interface — voice leads; turn-taking, interruptions, mid-sentence language switch.
3. Agents That Act — voice that gets things done; looks up/books/plans/builds via tools+APIs, conversation and actions as one.  ← OURS (primary). Secondary: 2.

## Judging (1-10 each, weighted)
| Weight | Criterion | What they say |
|---|---|---|
| 30% | Use of Higgs Audio | code-switching, expressive delivery, real-time turn-taking, interruption handling, tool calling. "If it would work the same with any generic TTS engine, strengthen this." |
| 25% | User Experience | usable, responsive, pleasant. "A rough prototype that feels good beats a polished one that doesn't." |
| 25% | Innovation | new idea or old one done differently; bonus for solving something people want solved. |
| 20% | Technical Execution | works reliably, reads cleanly. Judges go through the repo: clear setup + honest notes on what's unfinished. |

## Submission (Google Form, ~10 min; deadline not on page)
Form: https://docs.google.com/forms/d/e/1FAIpQLSe6IRDRto93iKdwTcRpCeZJ4pG1WIgJArIG7ksayCUOCjpMYw/viewform
1. Project info: name, track, one-sentence description, ≤200-word write-up (problem, audience, how it works).
2. Demo video: 2-3 min, project running + where Higgs is used. Working software, not slides. Public link, no access request. Optional: public try-it URL, live demo.
3. Repo: PUBLIC GitHub, pinned to exact commit SHA or tag (later pushes not seen). Source + setup + example I/O. NO API KEYS.
4. How you built it: each Higgs model/API and its role; what's novel / technically hard. ≤200 words.
5. Team: everyone, GitHub handle, what they did, known limitations.

## Not on page
Pre-built code policy, team size, demo length (beyond video), venue, prizes, schedule, FAQ. → ask at kickoff.
