# D — Frontier live voice APIs vs Higgs Realtime (final, Oct 23 2026)

Sources: OpenAI and Google primary docs fetched Oct 23 2026 (URLs below). Higgs cells come from local `docs/` (Boson mirror) and, in Phase 2, from the testers' measurements: **[A]** `A-tools.md` (tools, async), **[B]** `B-latency.md` (latency, turns, barge-in), **[C]** `C-session.md` (session, formats, idle, concurrency), [E] `E-twilio.md`. Where a tester contradicts the Boson docs or our old Gotchas, the tester wins and the cell says "corrected".

## GAPS WE FILL (layer + local agent, with evidence)

1. **Delegation to a backend that acts.** GPT-Live delegates to `gpt-6-*` or to the client. Higgs has only `_delegate(reason)`, which on 1.5 is still an instant "not configured" stub [A]. Ours: `higgslive.py` gives the GPT-Live client-delegation surface (`session.delegation.created`, commentary/thinking/instructions), and the backend is the user's own Claude Code/Codex session. Evidence: the async primitive it rests on holds on both models (open across turns 4/4 and 6/6, late output used 4/4 and 6/6 [A]). End to end it is green on 1.0 (clock+cat, hello.txt) [HI]. Our call carries the task text. GPT-Live's client mode carries only metadata [LD].
2. **Async scheduling semantics.** Gemini's `NON_BLOCKING` + `SILENT`/`WHEN_IDLE`/`INTERRUPT` [GT] map to our thinking (silent item, deleted before the result), commentary (real `function_call_output` after idle + drained playback + 1 s) and instructions (`session.update`, now verifiably acked [C]).
3. **Hosted tools.** GPT-Live's backend has search/shell/MCP/computer use. Higgs has `web_search` only, and `mcp` is inert. The local agent supplies shell, files, MCP and browser with the user's own permissions.
4. **Barge-in bookkeeping on WebSocket.** OpenAI WebRTC truncates server-side. On Higgs the client must flush 5–6 s of buffered audio, because the server sends no truncated event and the transcript `.done` is untruncated [B]. The layer clears playback on `speech_started`, and should also do so on `response.done` status cancelled, which arrives first.
5. **Over-calling guard (1.0).** 9/12 responses carry duplicate `delegate_task` calls [A]. Fill: open only the first call per response (a one-line change in the layer, not yet shipped), plus the "call once" description (9/12 → 4/12) [A].

## GAPS WE PARTLY FILL

6. **Tool skipping (1.5).** 1.5 claims "I've handed that off" with no call in 2/11 to 6/21 runs [A]. Our CLAIM regex detects it and the one-shot nudge fires, but 3/3 nudges on 1.5 died in `upstream_error`, so the recovery is unproven [A]. `tool_choice` cannot force a call (only `auto` works [HG]).
7. **Long calls.** No resume handle, no attach [C], a 32k context, an undisclosed duration cap (pending [C]), and a 300 s idle timer that only a finished turn resets [C]. Fill: keep the transcript and task state client-side, reconnect and replay text + `function_call` items, keep results hint-sized (≤800 chars). For a caller silently waiting on a long task, a text item + bare `response.create` every <5 min resets the timer [C, inferred]. GPT-Live-style warm replacement sessions are doable client-side but not built.
8. **Partial input transcripts.** OpenAI streams them with timestamps. Higgs gives `.completed` only. Fill: our own streaming STT on the mic, or skip (the tool call carries the task, so delegation doesn't need them).
9. **Out-of-band responses.** `conversation:"none"` is untested. Any `response` body triggers the greeting bug [HG]. Fill: side work in the backend or a separate text-mode session (cents, but it costs one of the ~2 generation slots per key on 1.5 [C]).
10. **Telephony.** OpenAI has native SIP in/out + DTMF. Higgs: WS only, but pcmu works natively both ways on both models [C], so a Twilio Media Streams passthrough needs no resampling [E]. DTMF and transfer would come from Twilio, not Higgs.
11. **Reliability under load (1.5).** `upstream_error` ~50% at 3 parallel sessions [A], with ~2 simultaneous generations per key [C]. Fill: one key per concurrent call, retry the response on `upstream_error` (the socket stays open [C]), and never run side sessions on the call's key. Cannot fix the server.
12. **Turn latency.** Caller wait is 0.92 s (1.0) / 1.00 s (1.5), 0.56 s of it VAD [B]. Fill: `silence_duration_ms: 400` saves ~70 ms safely. A client VAD + manual commit saves ~0.4 s (0.47/0.52 s) [B], at the cost of owning end-of-turn detection. Must also handle `response.created` without `response.done` after early commits [B].
13. **Image input.** OpenAI takes images, Gemini takes video. Higgs takes audio + text. Fill: the backend agent reads screenshots/files and returns a text hint.

## GAPS WE CANNOT FILL

14. **Full duplex and backchannels.** GPT-Live listens while speaking with no turn detector. Both Higgs models use the same VAD front end [B]. The 1.5 duplex claim is not in the API today.
15. **A real background model.** 1.5's announced thinking model is not reachable (the stub answers instantly [A]). We supply an *acting* backend, not Boson's thinking one.
16. **Affective dialog / proactive audio** (Gemini). Model-level, and gating replies needs `create_response:false`, which Higgs ignores [HI].
17. **Native SIP/WebRTC/DTMF, server-side truncation events, stereo, rate-limit headers**: transport and server features.

## Where Higgs 1.5 is behind 1.0 today
- **Tool skipping**: fake hand-off with no call, 2/11–6/21, vs 0/4 on 1.0 [A]. This is the worst regression for delegation.
- **Concurrency**: ~2 simultaneous generations per key vs 8/8 on 1.0 [C]. Errors: `upstream_error` in 8/42 responses, ~50% at 3 parallel sessions, vs 0/24 on 1.0 [A].
- **Latency**: +70–80 ms unloaded (first text 0.18 vs 0.11 s, model share 0.44 vs 0.36 s) [B]. Under load it falls into bands up to ~1.5 s [A].
- **48k in + 48k out fails** (`upstream_error` 2/2). Works on 1.0 [C].
- **Double utterance**: 1.5 speaks a preamble with the call, then the layer's bare ack produces a second line [A].
- 1.5 is better in a few places: exactly one call when it calls (1.0 duplicates), more task-aware in unrelated turns, grounded `web_search` (N=1) [A]. The **same 32k context** as 1.0 [A][C].

## Where Higgs beats the frontier APIs
- **Price**: ≈$0.016/min audio vs $0.05 GPT-Live and ≈$0.023 Gemini [P][GP][docs/pricing.md].
- **Async tool calls on the voice model itself** that stay open across turns and accept a late output (both models [A]), while Gemini 3.1 Flash Live is sequential and OpenAI Realtime documents a sync flow. Whether a call survives barge-in on Higgs is **pending**. Gemini documents that it cancels.
- **Formats**: pcm 8–48k and opus, pcmu for phones with no resampling [C]. Gemini input is PCM only.
- **Custom cloned voices** (`voice_<id>`) without an authorization gate. Built-in `web_search` (OpenAI Realtime has none [HM]).
- **Manual turns at ~0.5 s** commit→audio [B]. Mid-call voice/instruction swaps acked and applied [C].
